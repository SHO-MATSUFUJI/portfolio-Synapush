# 0007. Cognito Hosted UIは使わず、SPAからSRP認証で直接呼び出す

## ステータス

Accepted

## 決定

Cognitoのアプリクライアントはシークレットを発行せず（`generate_secret = false`）、認証フローは`ALLOW_USER_SRP_AUTH`と`ALLOW_REFRESH_TOKEN_AUTH`のみを許可する。ログイン画面はCognito Hosted UIを使わず、React SPA側で自前のログイン画面を実装し、SRPプロトコルでCognitoを直接呼び出す構成とする。

## 理由

Hosted UIはCognitoが提供する既製のログイン画面にリダイレクトする方式で、実害はなくても利用者（社内の担当者）に外部ドメインへ飛ばされる無駄なマイクロストレスを与えかねない。そのため、SPA内で完結するログイン画面にした。

なお、カスタムドメインを設定すればHosted UIでも自社ドメイン配下に見せることは可能だが、今回はまずシンプルな構成で実装し出来栄えを確認したい段階のため、その案は検討対象から外している。

ブラウザから直接呼び出すパブリッククライアントのため、シークレットは発行しない（シークレットはサーバーサイドでのみ安全に保持できるものであり、SPAに埋め込むと実質公開情報になるため）。認証フローもパスワードを平文で送らないSRPと、再ログインを避けるためのリフレッシュトークンのみに絞り、それ以外（USER_PASSWORD_AUTHなど）は許可しない。
