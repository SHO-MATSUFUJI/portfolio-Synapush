# 0001. ADRで意思決定を記録する

## ステータス

Accepted

## 決定

`docs/adr/` 配下に、軽量ADR（ステータス／決定／理由の3項目）を1決定1ファイルで記録していく。番号は連番で管理し、[`template.md`](./template.md) をコピーして作成する。

## 理由

Synapushは転職活動用のポートフォリオであり、成果物だけでなく「なぜその設計にしたか」という判断プロセスを提示できることに価値がある。README追記も検討したが、前者は経緯が上書きされ時系列を追えない。一方で、決定のたびに厳密なフォーマットで書くと運用コストが嵩み形骸化するため、項目数を最小限（3項目）に絞り、対象も絞ることで「残す価値はあるが書く負担は最小」を狙う。
