# 0005. GitHub ActionsからAWSへの接続はOIDCで行う

## ステータス

Accepted

## 決定

GitHub ActionsからAWSへの接続には、IAM OIDCプロバイダ経由の`sts:AssumeRoleWithWebIdentity`を使う。IAMユーザーを作成し長期のアクセスキーをGitHub Secretsに保存する方式は採らない。

信頼ポリシーの`sub`条件で`repo:<owner>/<repo>:ref:refs/heads/main`を指定し、ロールの引き受けをmainブランチで実行されるワークフロー（マージ後のCD）のみに限定する。PR時のCIはAWSアクセス自体が不要なため対象外とする。

## 理由

IAMユーザー方式は、発行したアクセスキーが漏洩すると失効させるまで使われ続けるリスクがあり、ローテーションの運用も必要になる。OIDCはワークフロー実行時にAWS側が短期的な認証情報を発行する方式のため、長期的な認証情報をGitHub Secretsに置く必要がなく、漏洩時の影響範囲も小さい。

`sub`条件でブランチまで絞ることで、フォークやその他のブランチからのワークフローではロールを引き受けられないようにし、信頼ポリシー単体でも意図しないブランチからのデプロイを防げるようにした。
